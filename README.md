# Семейная история · Куликов

Общедоступная статическая копия семейного сайта: **https://kulikage.github.io/Kulikov_tree/**.
Дерево Куликов находится в `tree-01/`. Главная страница резервирует место для
отдельного раздела Полянской; его данные и файлы сейчас отсутствуют.

Источник этой публикации — завершённая контрольная точка `tree-01/checkpoints/EXT-0002-after`.
Она создана **13 ноября 2026, 09:10:00 America/New_York** (14:10:00 UTC).
Сборка просмотрщика: **20261113140744-db25205dd8-cd4b5c8**, данные от
**13 ноября 2026, 09:07:44 America/New_York**. Точные даты, хеш исходного HTML,
хеш манифеста контрольной точки и хеши опубликованных материалов — в
[`publication.json`](publication.json) и [`site-manifest.json`](site-manifest.json).

Сайт сохраняет 54 отдельные записи, 50 родственных линий, 151 утверждение,
73 карточки источников и 24 версии тождества. Из них **28 записей обезличены**.
Статусы, концы связей, ссылки на основания и конкурирующие кандидаты сохранены.
Обезличивание не устанавливает факт жизни или смерти и не объединяет записи.

Имена оставлены у документированно умерших, у записей с явно указанным рождением
до 1916 года и у отдельно записанных родителей этих исторических поколений.
При неопределённом возрасте и у младших поколений имена, варианты имени,
биографические поля и раскрывающие их тексты скрыты. Отбор для публикации
не изменяет оценки исходного генеалогического дела.

Включены 28 проверенных изображений и вырезок, а также 8 выбранных документов-изображений.
Полные сканы рукописной схемы, фотографии с неопознанными людьми, частные сообщения,
сведения о передатчиках, журналы, заметки, реестры, контрольные точки, HTML-копии
внешних сайтов и не прошедшие проверку материалы не включены.
Выбранная вырезка строки 76 не содержит граф о родственниках; её координаты
и хеш источника записаны в манифесте публикации. Если образ исключён, карточка
источника прямо сообщает об этом. Ссылки на непубликуемые локальные файлы отсутствуют.

## Просмотр и размещение

Файлы не требуют сборки, внешних библиотек, CDN или сервера приложения.
Относительные ссылки работают под `/Kulikov_tree/`. Встроенные данные уже
обезличены, скрытые имена не загружаются в браузер. CSP запрещает автоматические
внешние запросы. Несколько проверенных публичных ссылок открываются только
по действию читателя; сайт не выполняет генеалогический поиск.

GitHub Pages: **Settings → Pages → Deploy from a branch → main → /(root)**.
Файл `.nojekyll` отключает обработку Jekyll. Секреты и дополнительные сервисы не нужны.
Не добавляйте сюда полный исследовательский проект или его Git-историю.

## Следующее обновление

Нужны Python 3.10+ и Pillow для проверки изображений и безопасных вырезок.
Средства публикации лежат в `tools/`; они читают источник и пишут только в новую
папку. Запускайте Python с `-B`, чтобы не создавать служебные файлы.

1. В отдельном checkout этого репозитория выполните `git pull --ff-only origin main`.
   Зафиксируйте существующие изменения; не используйте force push.
2. Выберите **новую завершённую контрольную точку только tree-01**. Проверьте
   её состояние, манифест и соответствующий просмотрщик. Не собирайте просмотрщик
   в исходном деле во время публикации. Незавершённые изменения другого агента
   включайте в следующую публикацию после закрытия их контрольной точки.
3. Создайте частный снимок **вне любого Git checkout**, например в соседней папке:

   ```powershell
   python -B tools/freeze_checkpoint.py --case '<полный путь к tree-01>' --checkpoint 'checkpoints/<завершённая-точка>' --out '../private-snapshot-next'
   ```

   Скрипт сверяет CSV с данными HTML, хеши контрольной точки,  все исходные файлы
   и изображения, копирует их побайтно и повторно читает источник для выявления
   конкурентных изменений. При несовпадении он останавливается. Папка снимка
   и её `snapshot-manifest.json` остаются частными и не коммитятся.
4. Вне репозитория подготовьте проверенную политику экспорта `private-policy.json`.
   Её поля: `source_build_id`, `source_html_sha256`, `exported_at` (ISO UTC),
   `public_person_ids`, `private_text_patterns` (регулярные выражения),
   `private_artifact_ids`, `previews`, `documents`, `public_urls`,
   `artifact_overrides`. Имена не добавляются в открытый список автоматически.
   Проверяйте возраст, возможную жизнь, переписку, текст всех полей и каждую
   выбранную страницу/скан, включая фон, подписи и метаданные.

   `previews` и `documents` — списки объектов `{"source":"путь/внутри/снимка.png"}`.
   Для вырезки укажите `crop: [left, top, right, bottom]`, `label` и точный
   `locator`. Путь превью должен совпадать с `_view.previews[].path` исходного
   HTML; путь документа — с `_view.original`. Разрешены PNG/JPEG без EXIF,
   комментариев и XMP. Вырезки сохраняются новыми PNG. Новые файлы по умолчанию
   исключены. Старую политику нельзя применять к новому хешу без проверки.
5. Экспортируйте в **новый пустой каталог вне снимка** и проверьте результат:

   ```powershell
   python -B tools/export_site.py --snapshot '../private-snapshot-next' --policy '../private-policy.json' --out '../public-next'
   python -B tools/verify_site.py --site '../public-next' --snapshot '../private-snapshot-next' --policy '../private-policy.json'
   node --check ../public-next/tree-01/viewer.js
   ```

   Экспорт использует интерфейс именно выбранной завершённой сборки. Если структура
   интерфейса изменилась, адаптер останавливается и требует пересмотра. Не обходите
   его проверки заменой данных демонстрационными примерами. При изменении счётчиков
   обновите описание этой версии в README.
6. Перенесите проверенные `index.html`, `.nojekyll`, `tree-01/`, `publication.json`
   и `site-manifest.json` в checkout. Удаляйте только устаревшие файлы предыдущей
   публикации, перечисленные в прежнем `site-manifest.json`, после проверки
   абсолютных путей. Сохраняйте прочие существующие файлы и изменения репозитория.
   Снимок, политику, результаты частного разбора и рабочие журналы не переносите.
7. Повторите проверку `tools/verify_site.py` уже для checkout. Откройте публичную
   копию в локальном браузере: главную, дерево, поиск, человека, линию, версию
   тождества, выбранный образ, выбранный документ, отказ для скрытого образа,
   возврат на главную и узкий экран. Проверьте под базовым путём `/Kulikov_tree/`.
8. Просмотрите `git diff --stat`, список подготовленных файлов и приватность
   встроенного JSON. Добавьте только файлы сайта и необходимые инструменты/инструкции,
   выполните commit и обычный push в `main`.
9. Дождитесь успешного `pages build and deployment` именно для нового commit.
   Проверьте живые страницы, изображения и документы, затем сопоставьте
   `publication.json` и хеши с подготовленным результатом. Сохраните частный отчёт
   о проверке вне репозитория. Настройку Pages повторять при обычном обновлении не нужно.

Политика отбора и полная локальная версия остаются у владельца. Отсутствие
скана в открытой копии не отменяет источник, его ограничения или статус утверждения.
